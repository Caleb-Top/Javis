# Javis L0-B 基础精致 3D 身体设计规格

**日期：** 2026-08-09

**状态：** 总体方向已批准，待子规格书面审阅与美术方向确认

**父规格：** `docs/superpowers/specs/2026-08-09-javis-life-os-master-design.md`

**接口规格：** `docs/superpowers/specs/2026-08-09-javis-l0a-life-kernel-design.md`

**范围：** 本地轻量 3D 渲染、角色资产清单、基础动作、生命表达映射、状态仲裁、透明窗口适配、性能降级、2D/光球兜底和桌面真实验收

**非授权声明：** 本文不授权实施，不选择最终商业角色资产，不修改 `G:\Javis` 正式源码，不触发 D 盘安装验收

## 1. 目标

L0-B 让 Javis 在生命内核尚处于出生阶段时，就拥有一个体面、精致、稳定、不廉价的基础 3D 身体。它不是最终数字人系统，而是可持续成长的身体底座。

L0-B 必须同时满足：

1. 第一次出现具有明确 Javis 视觉识别，而不是默认引擎模型；
2. 桌面透明窗口无黑边、白底、明显锯齿和资源闪烁；
3. 基础待机、呼吸、眨眼、视线和八类运行状态自然可辨；
4. 用户语音打断能立即终止说话表现；
5. 低配置、WebGL 失败、资产缺失和上下文丢失时自动降级；
6. 身体只消费 L0-A 的 ExpressionIntent，不定义身份、情绪或权限；
7. 3D 关闭、替换或损坏时，Javis 的身份、会话、记忆和任务继续存在。

## 2. 当前源码事实

### 2.1 已有基础

- Tauri 主窗口已配置 `transparent: true`、`decorations: false` 和 `shadow: false`；
- 默认窗口为 200×218，最小尺寸 132×158；
- `PetSurface` 已有拖拽、点击、右键菜单、皮肤切换、缩放和状态文字；
- `PetSkin` 目前支持静态透明 PNG、源图集、强调色和 CSS fallback；
- 已有 `javis-anime` 2D 皮肤和始终可用的 `javis-orb` CSS 兜底；
- `RuntimeStateCoordinator` 已输出 idle、listening、thinking、speaking、executing、blocked、error、offline 八态；
- `LiveOrbRenderer` 已证明 WebGL 透明画布可在当前 WebView2/Tauri 架构中运行；
- `VoiceCapture.onLevel` 提供麦克风输入电平，可继续驱动倾听表现；
- Tauri CSP 只允许本地脚本和资源，适合完全离线打包。

### 2.2 真实缺口

- `app/package.json` 没有 three、three-vrm 或其他 3D 依赖；
- `PetSkin` 没有 `kind`、模型路径、能力、动作、表情或许可证字段；
- `PetSurface` 只构建 2D sprite DOM，没有 3D canvas 生命周期；
- RuntimeSnapshot 只有表面状态和 detail，不能直接表示视线、强度、过渡、打断和状态版本；
- `VoiceCapture.onAudio` 是采集到的输入音频 base64，不是 TTS 播放逐帧数据，不能用于说话口型；
- 当前 SAPI/winsound 播放在原生侧，Web 前端拿不到输出频谱；
- TTS 只提供音频与时长，没有统一词边界或音素时间线；
- 没有 3D 资产、模型许可证、VRM 表情能力和包体预算校验；
- 没有 WebGL context lost 恢复、性能档位和 3D → 2D 自动降级；
- 没有嘴部、眨眼、视线、状态表情和姿态的统一权重仲裁。

## 3. 方案比较

### 3.1 方案 A：Three.js + VRM/GLTF + 2D/Orb 兜底

Three.js 本地打包进 Vite 产物，使用 VRM/GLTF 角色资产，沿用 PetSurface 的窗口、输入、拖拽和皮肤入口。3D 失败时自动回退现有 2D 或 CSS 光球。

优点：

- 与现有 WebView2、Vite 和 WebGL 证据最接近；
- 离线、CSP 兼容；
- VRM 提供相对标准的人形骨骼、表情和视素；
- 资产可替换，身体与身份解耦；
- 不引入大型游戏引擎；
- 可在浏览器预览与 Tauri 真机分别验证。

缺点：

- WebView2 单线程渲染需要严格性能预算；
- VRM 资产质量差异大；
- 透明窗口、alpha 边缘和设备兼容仍需 D 盘真机证据；
- 精细口型仍依赖后续 TTS 时间信息。

### 3.2 方案 B：纯程序化 3D 数字生命

使用 Three.js 基础几何体构成抽象能量人形或核心体，不引入外部角色模型。

优点是版权风险低、体积小、永远可用。缺点是很难满足“不要太丑”的人形陪伴感，容易像高级光球而不是 Javis 的身体。

此方案保留为零资产 3D 兜底，不作为默认外观。

### 3.3 方案 C：Unity、Unreal 或原生游戏引擎

优点是渲染和动画能力强。缺点是包体、启动时间、CSP、透明窗口、跨语言桥接、低配置降级和构建链成本过高。

此方案不进入 L0-B。

### 3.4 正式决策

采用方案 A，方案 B 作为 3D 零资产兜底，现有 2D 与 Orb 作为最终可靠兜底。

## 4. 视觉方向

### 4.1 初始风格

基础身体定位为“安静、克制、轻科技、精致的数字生命”。视觉上避免：

- 粗糙默认低模；
- 廉价页游质感；
- 过度幼态卡通；
- 过度性感化；
- 高写实恐怖谷；
- 大面积高亮霓虹和持续粒子轰炸；
- 频繁摇摆、跳动或夺取注意力的待机动作。

初始视觉签名：

- 蓝、青、紫的低饱和渐变；
- 柔和局部发光，不使用覆盖全身的强 Bloom；
- 清楚的头肩或半身轮廓；
- 稳定面部焦点；
- 干净材质与少量科技纹理；
- 轻微、缓慢、有呼吸感的待机运动；
- 与现有 Javis 图标和 Live 光球保持家族感。

### 4.2 暂不锁定的美术属性

L0-B 技术规格不锁定具体脸型、性别表达、年龄感、发型、服装和最终角色版权资产。进入实际资产选择前，应向用户展示至少三组同一技术预算下的可视化方向：

1. 轻科技人形；
2. 风格化动漫数字人；
3. 半抽象数字生命体。

选择依据是桌面小窗口辨识度、长期陪伴舒适度、动作自然度、许可证和性能，不只看单张大图效果。

## 5. 身体架构

L0-B 分为八个职责单一的模块。

### 5.1 AvatarManifest

描述角色资产、渲染能力、许可证、模型校验、默认动作、表达映射、性能预算和降级目标。

它不包含身份、关系、记忆和用户权限。

### 5.2 AvatarAssetRegistry

注册可用 3D、程序化 3D、2D 和 Orb 皮肤，验证本地路径、哈希、许可证与能力。注册失败不影响应用启动。

### 5.3 AvatarSurface

负责 canvas、renderer、scene、camera、lighting、resize、render loop、visibility 和 dispose。它不决定 Javis 当前情绪或状态。

### 5.4 AvatarController

接收稳定的 ExpressionIntent，驱动视线、姿态、表情、嘴部和过渡。

### 5.5 ExpressionMapper

把 L0-A 的 `base_state`、intensity、gaze 和 voice activity 映射为角色能力语义，不直接使用模型特定 BlendShape 名。

### 5.6 ExpressionMixer

统一合成嘴部、眨眼、视线、状态表情、呼吸和姿态，防止多个写入方互相覆盖。

### 5.7 PerformanceGovernor

根据 WebGL 能力、帧耗时、窗口可见性、资源压力和上下文丢失选择渲染档位。

### 5.8 AvatarFallbackCoordinator

负责 3D High → 3D Low → 程序化 3D → 2D → Orb 的单向安全降级和用户手动恢复。

## 6. 皮肤与资产清单

### 6.1 统一皮肤种类

现有 PetSkin 扩展为能力型清单，支持：

- `kind: vrm`；
- `kind: gltf`；
- `kind: procedural3d`；
- `kind: sprite2d`；
- `kind: orb`。

所有类型共享 ID、名称、描述、强调色、许可证和 fallback；只有 3D 类型拥有模型、动画和表达能力。

### 6.2 3D 清单字段

- 清单 schema 版本；
- 角色 ID 与版本；
- 资产 kind；
- 本地模型路径；
- 模型 SHA-256；
- 许可证标识、作者、来源和归属文件；
- VRM/GLTF 规范版本；
- 三角面数量；
- 材质和纹理数量；
- 最大纹理分辨率；
- 模型静态大小；
- 骨骼和表情能力；
- 视素能力；
- 默认镜头、缩放和锚点；
- 默认动作；
- 表达语义映射；
- 推荐性能档；
- 2D 与 Orb fallback ID。

### 6.3 初始资产预算

初始默认角色目标预算：

- 角色资产总大小不超过 25 MB；
- 最大单纹理不超过 2048×2048；
- 活跃材质数量不超过 8；
- 默认模型三角面不超过 80,000；
- 默认只启用一组主光、一组环境光和轻量阴影或无实时阴影；
- 不依赖外部 CDN、远程字体、远程贴图或运行时下载；
- 不启用布料、头发和全身刚体复杂物理作为默认能力。

这些数值是 L0-B 初始上限，不是美术最低质量。D 盘性能证据不足时只能向更低预算调整。

## 7. 渲染与窗口

### 7.1 渲染管线

- Three.js 与加载器打入本地 Vite bundle；
- renderer 使用透明 alpha；
- 颜色空间、纹理采样和透明预乘规则统一；
- 画布挂在现有 PetSurface 可控容器内；
- Pet 拖拽、单击、右键和设置入口继续由现有外层处理；
- 模型加载前显示稳定 fallback，不显示空白窗口；
- 模型加载失败只降级身体，不让主应用崩溃；
- `dispose()` 必须释放 animation frame、geometry、material、texture、renderer 和监听器。

### 7.2 镜头与构图

默认窗口尺寸很小，L0-B 以头肩或半身构图为主。镜头必须保证：

- 132×158 最小窗口仍能辨认面部与状态；
- 200×218 默认窗口轮廓完整；
- 用户缩放后不裁断关键面部；
- 角色视觉中心与点击热区一致；
- 拖拽透明边缘时不误触；
- 状态文字不覆盖面部和嘴部。

### 7.3 Windows 缩放与背景

必须在 100%、125%、150%、175% Windows 缩放下检查。透明边缘在浅色、深色、复杂壁纸和高对比背景下都不能出现黑边、白边或明显色溢。

## 8. ExpressionIntent v1 消费

L0-B 只消费 L0-A 定义的稳定语义：

| 字段 | L0-B 解释 |
|---|---|
| `schema_version` | 接口版本；不支持时进入兼容映射或 fallback |
| `revision` | 表达快照单调版本；旧版本不得覆盖新版本 |
| `base_state` | idle、attention、listening、thinking、speaking、executing、blocked、error、offline |
| `intensity` | 有界表达强度；不能直接映射为权限或永久情绪 |
| `gaze_target` | none、user、content、task 四种抽象目标，不包含屏幕坐标或摄像头权限 |
| `voice_activity` | silent、listening、speaking |
| `transition_ms` | 可中断的状态过渡时长 |
| `interrupt` | 立即中断嘴部、说话手势和低优先级动画 |
| `source_snapshot_revision` | 产生表达意图的生命快照版本 |
| `generated_at` | 生成时间 |
| `expires_at` | 过期时间；到期回归安全中性状态 |
| `explanation_code` | 有限原因码，用于诊断，不承载自由文本推理 |

字段语义由 L0-A 管理，L0-B 不自行扩展人格、关系或情绪字段。若身体需要模型专用 BlendShape、骨骼或动画名，只能在 AvatarManifest 和 ExpressionMapper 内部表示。

- `revision` 必须单调处理，旧 revision 不覆盖新状态；
- `expires_at` 到期后回到安全中性状态；
- `interrupt: true` 立即停止说话动作、嘴部包络和不可中断的普通动画；
- 未识别 `base_state` 回退 idle；
- 不根据 detail 文本猜测情绪；
- 不把 gaze_target 转换为摄像头观察权限；
- 生命内核不可用时使用现有 RuntimeSnapshot 兼容映射。

## 9. 基础状态表现

| 状态 | 姿态与视线 | 颜色与亮度 | 嘴部与动作 |
|---|---|---|---|
| idle | 中性、缓慢呼吸、自然眨眼 | 低亮蓝紫 | 嘴部关闭，低频微动作 |
| attention | 轻微抬头、视线转向用户 | 亮度平滑提升 | 停止无关待机动作 |
| listening | 稳定注视、轻微前倾 | 柔和青色 | 嘴部关闭，麦克风电平只驱动呼吸式反馈 |
| thinking | 视线轻微偏移、姿态收敛 | 蓝紫缓慢流动 | 不持续点头，不假装说话 |
| speaking | 视线回到用户、适度手势 | 稳定主色 | 使用说话包络，打断立即归零 |
| executing | 注意聚焦任务方向 | 主色略增强 | 克制循环，不用夸张忙碌动画 |
| blocked | 姿态暂停、表达谨慎 | 琥珀提示 | 不表现恐惧，等待授权 |
| error | 动作停止并保持可读 | 短暂红色提示后降低 | 不表现悲伤或痛苦 |
| offline | 低亮、低帧、有限呼吸 | 灰蓝 | 保留身体存在，不假装后端在线 |

状态表达要让用户能一眼区分，但不能依靠持续闪烁和大幅动作。

## 10. 动作与表情仲裁

### 10.1 通道

- lifecycle；
- posture；
- gaze；
- blink；
- facial expression；
- mouth/viseme；
- gesture；
- color/light；
- transition。

### 10.2 优先级

1. 安全与生命周期：offline、error、recovering；
2. 用户打断和 listening；
3. speaking mouth；
4. blocked 和 executing；
5. thinking；
6. idle 微动作。

高优先级不必完全清除低优先级。例如 speaking 可以继续自然眨眼，但 interrupt 必须立即清空嘴部与普通手势。

### 10.3 合成规则

- 每个通道只有 ExpressionMixer 写模型最终权重；
- 其他模块提交语义目标而不是直接写 BlendShape；
- 嘴部通道只控制口型相关权重；
- 面部状态不能把嘴部说话权重锁死；
- 眨眼覆盖眼睑但不改变视线目标；
- 状态切换采用可中断插值；
- 同一 revision 重复到达保持幂等；
- 长时间无新状态时逐渐回到中性，而不是冻结最后表情。

## 11. 语音、倾听与口型

### 11.1 输入电平

现有 `VoiceCapture.onLevel` 只用于倾听阶段的轻微视觉反馈，例如胸口或环境光呼吸。它不能驱动 Javis 说话口型，因为它表示麦克风输入。

### 11.2 输入音频

现有 `onAudio(audioBase64)` 是整段输入音频。L0-B 禁止在动画热路径反复解码该 base64，也禁止把它当成 TTS 输出。

### 11.3 L0-B 基础说话包络

当后端状态为 speaking 时，L0-B 使用受控的低精度说话包络：

- 根据 speaking 开始、结束和播放时长驱动；
- 嘴部开合幅度有上限；
- 包络加入确定性的停顿与平滑，不使用随机大幅抖动；
- 收到 barge-in、playback stop、request cancelled 或新 listening 时立即归零；
- 后端无法提供播放状态时，只显示轻微说话状态，不宣称音素同步。

### 11.4 后续高级口型

B3 可采用以下优先级：

1. TTS 音素或词边界时间线；
2. 服务端从实际 WAV 计算的能量包络；
3. 播放时长驱动的基础包络；
4. 仅 speaking 状态的轻微开合。

原生 SAPI、Edge TTS 和未来本地 TTS 都输出统一 LipSyncTimeline，身体不直接依赖具体 TTS 实现。

## 12. 性能和降级

### 12.1 性能档位

- **3D High**：完整基础材质、抗锯齿、平滑动作；
- **3D Low**：低分辨率、无实时阴影、低更新率、精简材质；
- **Procedural 3D**：零外部模型的轻量数字生命；
- **2D**：现有透明 PNG/图集；
- **Orb**：纯 CSS 或现有光球可靠兜底。

### 12.2 降级触发

- WebGL 不可用；
- 模型或贴图加载失败；
- context lost 且恢复失败；
- 持续帧耗时超过当前档目标；
- 内存压力或设备资源不足；
- 透明合成异常；
- 用户开启省电、减少动画或手动选择低档；
- 远程桌面或虚拟机环境能力不足。

### 12.3 性能目标

- 默认活跃状态目标不低于 30 FPS；
- 低档活跃状态目标不低于 20 FPS；
- 长时间 idle 可降低渲染频率，但状态过渡仍保持平滑；
- 后台、隐藏或非 Pet/Live 界面停止持续渲染；
- 3D 初始化不能阻塞对话、语音和 Code 界面；
- 资产加载或降级期间始终有可见 fallback；
- 性能调节不改变身份、状态语义和语音打断速度。

这些指标必须在 D 盘真实 WebView2 上记录，浏览器预览不能替代真机证据。

## 13. WebGL 丢失与恢复

收到 context lost 时：

1. 阻止默认不可恢复行为；
2. 停止 render loop；
3. 释放可释放资源；
4. 显示 2D 或 Orb；
5. 记录本地诊断；
6. 有限次数尝试恢复；
7. 恢复成功后重新加载资产并应用最新 ExpressionIntent；
8. 连续失败后保持低档，不循环重试和闪烁。

恢复不能重放旧 speaking 动画或过期状态。

## 14. 资产安全与许可证

- 模型和纹理由安装包或经用户批准的资产包提供；
- 运行时不从任意 URL 加载模型；
- CSP 保持 `script-src 'self'`；
- 每个资产包含许可证、作者、来源和允许用途；
- 构建时校验模型哈希、大小、格式和清单；
- 缺少许可证或来源的资产不能进入正式安装包；
- 资产解析失败不能执行脚本或访问外部网络；
- 用户自定义模型进入隔离导入流程，不直接覆盖默认资产；
- 用户选择更换身体不修改身份宪章。

## 15. 无障碍与用户控制

用户可以：

- 关闭 3D；
- 切换 2D 或 Orb；
- 调整身体大小；
- 关闭或降低动作；
- 关闭自动视线跟随；
- 关闭声音或口型；
- 设置省电档；
- 重置身体设置而不影响身份和记忆。

系统尊重 Windows 减少动画偏好。状态不能只靠颜色表达，状态文字和无障碍 live region 继续保留。

## 16. 与现有 PetSurface 的集成原则

- 保留现有 `createPetSurface()` 外部职责与输入行为；
- 皮肤类型决定 2D 还是 3D renderer；
- 点击、拖拽、右键和设置不由 3D 引擎重新实现；
- 3D canvas 不抢占必要 DOM 事件；
- PetSurface 统一拥有当前皮肤和 dispose 生命周期；
- 3D 模块失败由 PetSurface 切回 fallback；
- RuntimeStateCoordinator 作为 L0-A 不可用时的兼容来源；
- 不在 main.ts 增加多个平行状态订阅者直接写同一模型；
- 所有模型权重最终由 ExpressionMixer 控制。

## 17. 预览与美术确认

在接入正式 Pet 窗口前建立独立本地预览入口，能够：

- 固定切换九类状态；
- 调整 intensity、gaze、过渡和语音活动；
- 模拟打断；
- 切换性能档和 fallback；
- 切换浅色、深色和复杂壁纸背景；
- 模拟 132×158、200×218 和缩放窗口；
- 截取统一角度的视觉比较图；
- 显示资产、许可证和性能统计。

最终默认角色必须由用户在小窗口真实比例下确认，不能只根据大尺寸宣传图决定。

## 18. 自动化测试范围

### 18.1 纯逻辑测试

- 九类状态到表达语义的确定性映射；
- ExpressionMixer 通道优先级；
- 打断立即清空嘴部和手势；
- PerformanceGovernor 档位切换；
- FallbackCoordinator 单向降级和手动恢复；
- asset hash、大小、纹理和能力校验。

### 18.2 DOM 与生命周期测试

- 3D 皮肤创建 canvas；
- 2D 皮肤不创建 3D renderer；
- 模型失败显示 fallback；
- dispose 取消 animation frame 并释放监听；
- 切换皮肤不累积 canvas 和 WebGL context；
- 拖拽、点击、右键和设置行为不回归；
- 状态文字和无障碍 live region 保留。

### 18.3 构建测试

- TypeScript strict 构建通过；
- Vite 产物无 CDN 和外部脚本；
- CSP 不需要放宽到任意远程来源；
- 安装包包含清单声明的资产；
- 资产哈希与许可证报告完整；
- 2D/Orb fallback 即使删除 3D 资产仍能构建和启动。

### 18.4 D 盘真实验收

- 透明窗口无黑边、白底和明显锯齿；
- 100%、125%、150%、175% 缩放检查；
- 浅色、深色和复杂壁纸检查；
- 默认与最小窗口尺寸检查；
- 拖拽、点击、右键和缩放检查；
- 语音倾听、思考、说话、打断和恢复检查；
- WebGL context lost 与 3D → 2D 降级检查；
- 低配置档性能、内存和启动时间记录；
- 重启后皮肤设置保留；
- 卸载和重装不破坏用户选择的数据与模型目录。

## 19. 首次身体体验验收

完整场景为：

1. Javis 以基础 3D 身体在桌面安静待机；
2. 没有模型加载闪白、黑框或空白窗口；
3. 用户呼唤时视线与姿态进入 attention；
4. 麦克风倾听时身体稳定，不把用户声音表现成 Javis 说话；
5. 思考时有克制且连续的表现；
6. 回答时出现基础说话包络；
7. 用户打断时嘴部、声音和手势立即停止；
8. 请求取消后不会被迟到终态拉回旧 speaking；
9. 回合完成后平滑回到 idle；
10. 禁用 WebGL 后自动显示 2D 或 Orb，Live 与 Code 仍可正常使用。

十步全部成立才算 L0-B 基础身体闭环。单张好看的静态截图不能替代该验收。

## 20. 实施拆分原则

本子规格适合一个独立实施计划，任务依赖顺序为：

1. 资产清单和校验；
2. Three.js/VRM 本地渲染最小管线；
3. PetSurface 多种 skin kind；
4. ExpressionIntent 和兼容状态映射；
5. ExpressionMixer 与基础动作；
6. 基础说话包络和打断；
7. 性能治理、context lost 和 fallback；
8. 预览工具与美术对比；
9. 构建、许可证和包体校验；
10. D 盘透明窗口与性能验收。

每项必须先有失败测试或可重复的视觉基线。不得在同一任务中同时更换角色资产、状态协议、语音播放架构和 Pet 窗口行为。

## 21. 非目标

- 不在 L0-B 实现影视级数字人；
- 不引入 Unity、Unreal 或完整游戏引擎；
- 不做复杂布料、头发和全身物理；
- 不宣称基础包络是音素级口型；
- 不使用麦克风输入驱动 Javis 说话口型；
- 不让身体读取隐藏推理或长期记忆正文；
- 不让身体修改身份、关系、权限或生命状态；
- 不从 CDN 或未授权网站自动下载角色；
- 不删除 2D 和 Orb fallback；
- 不把皮肤选择当作人格选择；
- 不因 3D 失败阻止 Live、Code、语音或设置启动。

## 22. 出口标准

L0-B 只有同时满足以下条件才可进入 B1/L1：

1. 默认基础 3D 在桌面小窗口中体面、稳定、可辨认；
2. 透明窗口在 D 盘真实环境无黑框和白底；
3. 九类状态有一致、克制、可打断的表现；
4. 用户打断能立即终止声音相关身体表现；
5. 3D High、3D Low、程序化 3D、2D 和 Orb 降级路径完整；
6. WebGL、资产和上下文故障不导致主应用崩溃；
7. 身体只依赖 ExpressionIntent 或明确兼容层；
8. 身体替换不改变身份、会话、关系和模型配置；
9. 资产许可证、哈希、预算和离线打包证据完整；
10. 现有 Pet 拖拽、点击、右键、缩放和设置无回归；
11. 现有语音、打断、Live、Code 和安装基线无回归；
12. 用户已在真实小窗口比例下确认默认视觉方向；
13. 所有未在 D 盘执行的视觉和性能项目明确标记为未验收。
