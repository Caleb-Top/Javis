# Javis 右键交互、独立设置与统一视觉设计

日期：2026-07-29

## 1. 目标

本轮只调整 App 原生外壳的交互和视觉呈现，不改变 Javis 五大系统、Python 后端、Code Web 功能、记忆、权限和工具能力。

需要解决：

1. Live 蓝球第一次右击只切换桌宠模式，第二次右击才显示菜单。
2. Live 蓝球切换到默认动漫桌宠后产生“右击换皮肤”的错觉。
3. 自定义快捷项只有通用文本框，不清楚该填写路径、链接还是组合键。
4. 设置依附在 Code 抽屉中，没有独立设置体验。
5. 当前应用图标仍是旧动漫素材，与 Javis 蓝色动态标不一致。
6. Code、设置、诊断和首次引导的边界、圆角和色彩语言不统一。

## 2. 保留范围

- 保留 Live、桌宠、Code、诊断、首次引导的现有功能入口。
- 保留桌宠皮肤选择和桌宠尺寸设置。
- 保留右键菜单固定的“设置”和“Code”两项，以及最多三个自定义项。
- 保留完整 Python 后端与五大系统架构。
- 保留 Code 中加载 `http://127.0.0.1:8080/` 的完整 Web 功能界面。
- 不修改蓝图、记忆、模型、训练结果或用户数据。

## 3. 根因

`main.ts` 中 Live Canvas 的 `contextmenu` 监听只调用 `setDesktopMode("pet")`。桌宠自己的菜单监听只存在于 `PetSurface`，因此首次右击不会继续打开菜单。

Live 使用 WebGL 蓝球，桌宠默认使用 `javis-anime`。模式切换同时改变了视觉载体，导致首次右击看起来像切换皮肤。

设置由 `ControlDrawer` 的 `settings` 标签承载。桌宠菜单点击“设置”时先打开 Code，再打开控制抽屉，因此设置始终覆盖在 Code 上。

## 4. 方案选择

采用统一原生外壳改造：

- 保留业务功能和现有后端。
- 抽离菜单控制、设置页面和视觉令牌。
- 为 Live、Pet、Settings、Code 建立明确的桌面模式。

不采用仅修事件的最小补丁，因为它无法解决设置耦合和视觉割裂。

不采用完整前端重写，因为会扩大 Code、Live 和后端桥接的回归范围。

## 5. 右键菜单交互

### 5.1 Live 模式

- 第一次右击 Live 蓝球立即打开菜单。
- 蓝球保持当前 WebGL 渲染，不切换桌宠皮肤。
- 原生窗口根据屏幕剩余空间向左或向右扩展菜单区域。
- 菜单关闭后恢复原始 Live 窗口尺寸和屏幕位置。

### 5.2 Pet 模式

- 右击当前桌宠皮肤立即打开同一菜单。
- 再次右击、点击菜单外部、按 `Escape`、拖动窗口或执行菜单命令时关闭菜单。
- 菜单始终包含“设置”和“Code”，随后显示最多三个已完成配置的自定义项。

### 5.3 状态模型

菜单控制器记录：

- 来源模式：`live` 或 `pet`。
- 展开状态。
- 菜单方向：`left` 或 `right`。
- 展开前的窗口尺寸和位置。

菜单关闭时按来源模式恢复窗口，不能统一恢复为桌宠尺寸。

## 6. 独立设置页面

新增 `settings` 桌面模式，使用同一个 Tauri 主窗口，不创建第二套后端或重复运行时。

进入设置时记录来源模式。关闭设置后返回进入前的 `live`、`pet` 或 `code`。

设置页面不挂载在 Code iframe 上方，也不调用 `openCodeSurface()`。

页面结构：

- 顶部：Javis 设置、返回按钮、窗口拖动区域。
- 左侧导航：常规、桌宠、快捷项、外观。
- 右侧内容：当前分类的设置项。
- 底部：自动保存状态和必要的恢复默认操作。

现有 Code 控制区域中的设置入口改为打开独立设置模式。`ControlDrawer` 不再承载桌宠设置表单。

## 7. 自定义快捷项

每个槽位由以下字段组成：

- 菜单名称：右键菜单中显示的名称。
- 类型：Javis 功能、应用或文件、网页、组合键。
- 类型对应的目标控件。
- 配置状态。
- 清除按钮。

### 7.1 Javis 功能

目标使用下拉框，不允许自由输入。候选值：

- 打开 Live
- 打开 Code
- 打开设置
- 打开诊断

### 7.2 应用或文件

- 显示目标路径输入框。
- 提供系统级“浏览”按钮，使用 Tauri 原生文件选择窗口。
- 允许 `.exe`、`.lnk`、普通文件和目录。
- 保存时检查目标是否存在。

### 7.3 网页

- 输入框标签明确为“网页地址”。
- 示例为 `https://example.com`。
- 只接受 `http` 和 `https`。

### 7.4 组合键

- 使用“开始录制”按钮捕获组合键。
- 显示规范化结果，例如 `Ctrl+Shift+P`。
- 至少包含一个修饰键。

### 7.5 保存与显示

- 设置自动保存。
- 状态显示“已保存”“配置不完整”“格式错误”或“目标不存在”。
- 只有名称、类型和目标全部有效的槽位才出现在右键菜单中。
- 未配置槽位不占菜单位置。

## 8. 应用图标

使用用户选择的 C 候选，即真实 `thinking` 状态渲染帧。

处理要求：

- 从 WebGL Canvas 直接导出带透明通道的 PNG，不能使用带黑色截图背景的裁切图。
- 保留蓝色主体和柔和外发光。
- 保证中心和外环在正方形安全区内。
- 生成 16、24、32、48、64、128、256 和 512 像素资源。
- 生成 Windows `.ico`，并更新 Tauri、任务栏、托盘、开始菜单和安装包资源。
- 16 和 24 像素版本需要单独检查，不能只依赖浏览器缩放观感。

## 9. 视觉系统

### 9.1 色彩

设置与完整窗口采用浅灰中性色：

- 页面背景：`#EEF1F5`
- 主表面：半透明白色
- 主文字：深灰蓝
- 次文字：中性灰
- 强调色：从蓝色动态标提取的冷蓝

避免大面积纯黑、强描边和多色渐变。

### 9.2 圆角

- 完整窗口外壳：20px
- 主内容面板：14px
- 输入框和下拉框：10px
- 图标按钮：圆形
- 命令按钮：8px 到 10px
- 桌宠右键菜单：保留紧凑胶囊形

### 9.3 边界与模糊

- Tauri 主窗口继续使用透明、无系统装饰。
- 完整窗口外壳使用半透明 1px 描边、柔和内高光和低强度阴影。
- 使用 `backdrop-filter` 时提供不支持模糊的纯色回退。
- `body`、App 根节点和 iframe 容器统一裁切，防止四角溢出。
- Live 和桌宠模式保持透明，不添加方形背景。

### 9.4 Code

- Code iframe 功能不变。
- 原生 Code 工具栏、iframe 容器和窗口边界改为浅灰统一外壳。
- iframe 四角由宿主容器裁切。
- 不向旧 Web 页面注入破坏性样式。

### 9.5 其他完整界面

诊断、首次引导和确认界面复用同一组背景、圆角、边界、阴影和按钮令牌，消除不同模块各自定义风格的问题。

## 10. 安全与错误处理

- 应用或文件由系统文件选择器返回路径，执行前仍需重新检查存在性。
- 网页继续限制为 `http` 和 `https`。
- 组合键继续走 Rust `SendInput`，不执行 Shell 字符串。
- 设置加载失败时回退默认值，不能阻塞 Live 启动。
- 图标生成失败不能覆盖现有可用图标。
- 设置页打开失败时恢复来源模式。

## 11. 测试与验收

### 11.1 自动测试

- Live 第一次右击产生“打开菜单”动作，而不是仅切换 Pet。
- Live 菜单关闭后恢复 Live 尺寸和位置。
- Pet 菜单关闭后恢复 Pet 尺寸和位置。
- 设置从 Live、Pet、Code 进入后分别返回正确模式。
- 设置入口不调用 `openCodeSurface()`。
- 四种快捷类型生成正确的字段模型、提示、验证和菜单状态。
- 图标候选为 `thinking` 状态，输出资源尺寸完整。

### 11.2 浏览器视觉检查

- 设置页在 1280×820、960×700 和 760×560 下无重叠或溢出。
- 快捷项类型切换后字段、说明和状态正确。
- Code、设置、诊断和首次引导四角一致。
- 16、24、32、64 和 256 像素图标可辨识。

### 11.3 原生 Tauri 检查

- Live 蓝球第一次右击直接出现菜单且不换皮肤。
- 桌宠右键菜单、拖动、左右展开和关闭恢复正常。
- 设置为独立浅灰页面，Code iframe 不可见。
- 系统文件选择器可选择应用或文件。
- 组合键可以录制并通过 Rust 执行。
- Windows 任务栏、托盘和窗口图标均为 C 思考状态蓝标。
- 窗口透明四角没有黑边、白边或 iframe 方角泄漏。

## 12. 完成定义
