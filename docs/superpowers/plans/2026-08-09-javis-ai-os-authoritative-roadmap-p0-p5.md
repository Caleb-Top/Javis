# Javis AI OS P0–P5 权威总路线图

> 版本：ROADMAP-V1-2026-08-09  
> 状态：执行中  
> 产品北极星：`BIRTH-V4-2026-08-09`  
> 工程主计划：`MASTER-PLAN-V2-2026-08-09`  
> 近期执行细则：`2026-08-09-javis-authoritative-p0-p1-execution-plan.md`

## 1. 这份路线图解决什么

Javis 不是只修好语音就结束的桌面工具。两份总纲描述的是同一件事的两个层次：

- `BIRTH-V4` 定义“Javis 是谁”：它有当下、记忆、心思、分寸和成长，但不宣称具有真实意识。
- `MASTER-PLAN-V2` 定义“怎样造出来”：从 P0 到 P5 逐层建造可验证的器官。
- 本路线图定义“现在做到哪、下一步做什么、什么时候才算完成”。

工程顺序由依赖和真实验收决定，不用“生命年表”的叙事顺序代替技术依赖。

## 2. 不可变规则

| 路径 | 角色 | 不可变规则 |
|---|---|---|
| `G:\Javis` | 唯一最终源码、依赖、缓存、编译、构建与 main | 开发期间不直接改；审查通过并得到用户明确同意后才合入 |
| `G:\Javis-worktrees` | 隔离开发区 | 代码修改、TDD、批判审查和大项测试只在这里进行 |
| `D:` | 真实用户测试端 | 只放最终候选包，执行安装、运行、升级、卸载与真实验收；不编译 |
| C 盘 | 非项目工作区 | 不写项目修复、构建缓存或交付物 |

贯穿所有阶段的纪律：

1. 未经用户明确同意，不下载、安装依赖或模型。
2. 每个行为改动按“红线测试 → 实现 → 绿线 → 批判审查 → 独立提交”执行。
3. 测试通过不等于产品完成；需要真实硬件、模型、网络或用户感知的项，必须在 D 盘候选二进制上验收。
4. 验收数字只使用当次命令的真实输出，不沿用长期文档中的旧计数。
5. 原始音频、API Key、令牌、未脱敏会话和工具参数不进诊断、记忆或日志。
6. 产品可以呈现生命感与陪伴感，但必须诚实说明 Javis 不具有真实意识。

## 4. 依赖图与实际执行顺序

```text
P0-R 语音根因修复
        ↓
P0-O 可观测性 + 真实 stall harness
        ├──→ P1.1 版本/发布基线 ──┐
        └──→ P1-M 统一模型中心 ────┘  AND
                                      ↓
                            v3.0.1 唯一候选二进制
                    ↓
           D 盘真实验收 + 24h 浸泡
                    ↓
             P1 可信发布冻结
                    ↓
              P2 记忆系统
                 ┌──┴──┐
                 ↓     ↓
              P3 认知  P4 身体
                 └──┬──┘
                    ↓
              P5 管家/成长
```

裁决：

- P0 必须直接验收最终要发布的 v3.0.1 二进制，不先验收 v3.0.0 再换包。
- P1.1 与 P1-M 是候选冻结的 AND 条件；两者任一未过门都不能构建最终候选包。
- P2 是 P3、P4 和 P5 的统一记忆底座。
- P3 和 P4 只有在 `life.state/persona/event/memory identity` 共享 schema 冻结后才可以用不同 worktree 并行；P5 同时消费认知、身体、记忆和权限契约。
- “整体计划存在”不意味着可以绕过 P0/P1 可靠性门禁同时修改所有内核。

## 6. P0：先让它真正能听、能回、不卡死

### P0-R 根因修复出口

- 麦克风 owner/lease 在断线、取消、发送失败、重复 stop 和旧/新 handler 交叠时都符合世代契约。
- 新世代重连不重放上一世代 `transcript.final`，旧 handler 不能释放新 lease。
- 连续语音 WebSocket 自动重连，退避封顶、ready 后重置，pause/stop 后绝不自行复活。
- `transcript.final` / `transcript.empty` / `audio.error` 每轮只有一个终态。

### P0-O 可观测性与防永久思考

- 前端实施 accepted 3s、first response 15s、overall 60s 三阶段看门狗，超时后清请求、取消后端并恢复 UI。
- 真实 loopback stall 分别模拟不 ack、ack 后无首字、首字后永久挂起。
- 诊断只输出有界计数、队列、世代、任务数和脱敏标识；原始语音、文本和密钥不出现。
- 候选构建前完成自动化回归；D 盘上使用同一候选二进制重放真实时限。

### P0 D 盘出口

- 30 个连续成功真人语音回合，无永久思考。
- 关闭/重开 Live 与强制断线重连各 10 次，owner ≤1，无残留任务。
- 三档 stall 按 3/15/60 秒契约退出 thinking；迟到事件不复活。
- 20 条中文真人语料无空识别，平均 CER <20%，报告 P95 与最差项，不挑样本。
- 打断 P95 <500ms，终态后 1s 内恢复 listening，停说到首响应目标 P95 <1s（低配 <1.5s）。
- 同一二进制完成 24h 浸泡；无 owner、任务、队列、麦克风和测试端口残留。

## 7. P1：让它能被可信地安装、配置、升级

### P1-M 统一模型中心

1. Live 与 Code 从任一入口打开同一 SettingsSurface，不保留 Code 第二套模型真相。
2. 共享开关开启时共用 profile；关闭时 Live/Code 可分别选本地/云端、供应商、model ID、endpoint 和凭据引用。
3. 覆盖 DeepSeek、GLM、Kimi、Qwen、OpenAI、Anthropic；无 Key 可见内置推荐，有 Key 合并账户 `/models`，并允许自定义兼容 ID。
4. 基础安装包不含大模型权重；R1 作为独立附加包，与主安装包并列，用户可改目录，导入前验 manifest/hash/空间。
5. 安装向导显示来源、许可证、大小、目标目录和分阶段真进度；支持暂停、继续、取消、断点恢复和失败回滚。
6. 安装计划用不可变 plan token 绑定来源、hash、大小、许可证、目录和应用目标；确认后修改任一字段都必须重新生成并确认计划。
7. 安装本地模型只在用户明确同意后进行；`trust_remote_code=false`，只自动适配白名单架构/格式。
8. Ollama 未启动、崩溃、重启或端口变化时有可见状态和可恢复引导；本地失败不覆盖云端 profile。
9. 干净基础包在没有 R1、没有本地模型且没有云 Key 时必须立即进入可操作引导，不得默认调用 `deepseek-r1:8b` 并等待约 30 秒才失败。
10. 模型配置必须有 schema version、原子写、并发保护和迁移测试；安装前就能选用户数据根，不只依赖临时环境变量。

内部实现顺序固定为：`契约/schema/红线 → Code 统一入口与四路由矩阵 → 无模型快速引导与 Ollama 生命周期 → route-scoped 安装状态机与 HF 安全门 → 六供应商完整目录 → 原子持久化/迁移/三次重启/D 盘验收`。不先做安装 UI 再回头修路由语义。

### P1-R 可信发布

- 生成式单一版本源覆盖 Python/Node/Tauri/Rust/NSIS/产物名，一致性测试防漂移。
- preflight 理解 worktree 与 G 盘共享依赖，数据类缺件如实标识，不把真缺陷 skip 掉。
- 唯一发布命令先跑 Python/App/Rust/release/installer source 门，不绿不打包。
- 候选 manifest 至少包含 `version/source_commit/runtime_sha256/package_sha256/test_summary/acceptance_status/candidate_id`。
- 最终 release manifest 引用同一 candidate/package hash 及 D 盘验收/浸泡报告 hash；包哈希变化则证据作废。

## 10. P4：让它的内在状态有身体和声音

| 步骤 | 交付 | 硬门禁 |

| P4.1 | Three.js + three-vrm 透明 AvatarSurface | 本地 bundle、无 CDN；WebGL 失败自动降 2D/CSS orb；创建/销毁无上下文泄漏 |
| P4.2 | 合规 VRM 资产 + expression/viseme 映射 + 程序化头像兜底 | license/作者/表情/视素自动校验；模型丢失不白屏 |

| P4.4 | 后端 `life.state`：认知→人格→情绪→行为→表达 | 表情与 mouth 双写由单一 blend-weight 合成器仲裁；未知状态降 Idle |
| P4.5 | VoicePersona 影响音色/语速/音量/停顿，缓存键包含人格 | 无 persona 时与 P0 输出兼容；不同人格不串缓存 |
| P4.6 | Live/Pet 共享单一 AvatarSurface 实例 | 两模式无重复 WebGL 上下文；窗口透明无黑边；P0 六门禁复验 |

硬件分级是 P4 的必选功能，不是宣传文字：

- 最低：4 核/8GB/无独显 → 2D 身体 + 小模型/云模型，目标首响应 <1.5s。
- 推荐：16GB/6GB 显存 → 简化 3D + 适配本地模型，目标 <1s。
- 高配：强 CPU/8GB+ 显存 → 完整 3D/本地语音，目标 <500ms。
- 任一能力降级后 Javis 仍可对话、可记忆、可解释当前降级，不能只显示“无法运行”。

## 12. 贯穿 P0–P5 的五条横向主线

### X1 轻安装与按需模型

- 主程序不捆大权重；用户可只用云 API，也可从向导经同意安装本地模型。
- R1 始终是可选附加包，不重新演变为 7GB 主安装包。
- 运行时、模型、记忆和数据目录均尊重用户选择，不静默回落固定 AppData。

### X2 延迟与流式体验

- 防卡死上限是 3/15/60s；产品延迟目标仍是本地首响应 P95 <1s，低配 <1.5s，打断 <500ms。
- P2–P5 新增记忆、计划、情绪、双孪生时，必须分别有“不进实时路径”或“明确预算”的测试。

### X3 低配降级与跨平台

- 核心会话、记忆 schema、权限和 life state 保持跨平台；系统工具与渲染皮肤用 adapter 隔离。
- Windows 是当前可发布基线；macOS/Linux 在核心契约稳定后建独立移植工作树和真机验收，不用“Tauri 能编译”代替真平台验收。

### X4 边界、隐私与用户主权

- 记忆归用户所有；本地优先；可查、可忘、可导出。
- 危险操作的 deny 是内核底线，不是可被“信任”覆盖的 UI 开关。
- 自学习/自生成代码在沙箱、测试、审批和可回滚之前不进生产。

### X5 证据与可观测性

- 每阶段产出：源码提交、动态测试清单、批判审查、D 盘验收记录、产物 hash 和未验收项。
- 任何候选包重建都使之前的二进制验收与浸泡证据失效。

## 13. 执行波次

### Wave 0：当前可发布出生闭环

1. 完成 P0-O 同 session 重连世代修复、诊断一致快照、全量回归和整时限 stall。
2. 独立审计并实现 P1-M：删除 Code 第二套模型真相，完成安装状态机、Ollama 恢复和路由隔离。
