# Javis 源码区与测试区规则

更新时间：2026-08-20

## 目录职责

| 路径 | 职责 | 规则 |
|---|---|---|
| `G:\Javis` | 主源码、依赖、编译和集成区 | 唯一正式源码区和当前 Life OS 集成主线；已验证工作包直接形成可回退提交。 |
| `G:\Javis-worktrees` | 历史隔离开发现场 | 只读参考或迁移来源；不得继续作为正式阶段的事实权威。 |
| `G:\Javis\.codex\worktrees` | 可选隔离开发区 | 仅在共享文件冲突或高风险迁移需要时使用；完成后必须合入 `G:\Javis` 并删除平行权威。 |
| `G:\Javis\tmp` | 临时文件、测试夹具和工具缓存 | 测试命令必须显式设置 `TEMP`、`TMP` 到这里，避免临时源码夹具落到 C 盘。 |
| `G:\Javis-build-cache` | 外部依赖与构建缓存 | npm、Corepack、Rust 和安装包中间产物进入此处；不进入 Git。 |
| `D:\Javis` | 真实用户测试端 | 只用于安装后体验、升级、卸载和真实用户路径验收；不作为源码、依赖或构建缓存。 |
| C 盘用户目录 | 系统和应用默认用户区 | 开发阶段不主动写 Javis 源码、构建物、缓存或测试数据。只有真实安装包按产品设计运行时，才允许验证其用户数据行为。 |

## 执行规则

1. 不把 D 盘当开发区，不把 C 盘当缓存区。
2. 所有源码修改先在 G 盘完成；每个工作包使用定向测试、关联回归和构建证据后提交。
3. 运行 Python、Node、Rust 验证时设置：

   ```powershell
   $env:TEMP='G:\Javis\tmp'
   $env:TMP='G:\Javis\tmp'
   ```

4. Rust 验证使用 G 盘工具链与缓存；新增依赖必须固定版本并形成锁文件证据。
5. 运行时数据库、会话日志、录音片段和临时补丁不进入提交。
6. D 盘验收只复制或安装来自已提交源码的精确产物；不得现场修改安装目录冒充修复。
7. Life OS L0/L1 已于 `80813d6c` 合入 `main`。后续 L0-B、L2-L8 均以当前 `main` 为唯一集成基线。
8. 共享合同实行单写者：身份归 LifeService，记忆归 MemoryService，环境事实归 EnvironmentService，承诺归 IntentService，行动授权归 ActionService，迁移归 ContinuityService。
9. 前端、模型、身体、工具和关系投影只能消费受治理快照，不能直接写入上述权威状态。
10. 工作包提交不得夹带运行时数据库、会话内容、录音、屏幕帧、缓存、生成资产或未核准模型。

## Git 与并行规则

1. `main` 保持可构建；并行智能体必须拥有互不重叠的文件集合。
2. 依赖工作包、合同工作包、产品实现和发布证据分开提交，便于逐层回退。
3. 发现并发改动时保留并适配，不覆盖、不重置、不删除他人工作。
4. 每个阶段先锁定 schema、隐私、权限、TTL、幂等和恢复合同，再接入生产路径。
5. 自动化通过不等于 D 盘真机通过；未执行项必须标记 `NOT EXECUTED`。

## 当前 Life OS 收口标准

- L0-B 身体只消费 `ExpressionIntent v1`，支持 3D、2D、Orb 降级和确定性释放。
- L2-L8 每阶段都有真实用户闭环，不以空 API、孤立类或模拟事件宣称完成。
- 主体识别失败、权限缺失、来源过期、证据不完整和迁移不确定时统一 fail closed。
- 关系、熟悉度、情绪、模型输出和身体表现永远不能扩大权限。
- 删除、纠错、升级、分支和终止具有可验证的闭包与回退证据。
